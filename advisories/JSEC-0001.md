# JSEC-0001 — XSS in HTMLHelper::link() and HTMLHelper::iframe()

| | |
|---|---|
| **CVE** | CVE-2026-90906 |
| **Upstream advisory** | [20260901](https://developer.joomla.org/security-centre/1081-20260901-core-xss-in-htmlhelper-link-method.html) · [GHSA-qhxg-999j-94vf](https://github.com/advisories/GHSA-qhxg-999j-94vf) |
| **Severity** | Medium (upstream rating) |
| **Affected** | Joomla 1.5.0 – 5.4.8, 6.0.0 – 6.1.3 |
| **Verified on** | Joomla 3.10.12 — **confirmed vulnerable** |
| **File** | `libraries/src/HTML/HTMLHelper.php` |
| **Patch** | `patches/0001-*.patch` |

## The vulnerability

`HTMLHelper::link()` in 3.10.12 was three lines with no escaping anywhere:

```php
public static function link($url, $text, $attribs = null)
{
    if (is_array($attribs))
    {
        $attribs = ArrayHelper::toString($attribs);
    }

    return '<a href="' . $url . '" ' . $attribs . '>' . $text . '</a>';
}
```

`$url` is interpolated straight into a double-quoted attribute, so a `"` in the URL
closes the attribute and everything after it is parsed as further attributes. Array
attribute *values* go through `ArrayHelper::toString()`, which builds `name="value"`
pairs without escaping the value, giving a second identical breakout.

`HTMLHelper::iframe()` has the same shape with the same bug, in `src` and `name`.
The upstream fix covers both, and so does this patch.

## Proof

From `tests/probe.php` against stock 3.10.12 — the `detail` column is the actual
markup returned:

```
CVE-2026-90906/link-url-breakout     VULNERABLE  <a href="" onmouseover="alert(1)" >click</a>
CVE-2026-90906/link-attr-breakout    VULNERABLE  <a href="https://example.test" title="" onfocus="alert(1)">click</a>
CVE-2026-90906/iframe-url-breakout   VULNERABLE  <iframe src="" onload="alert(1)"  name="frame"></iframe>
CVE-2026-90906/benign-url-preserved  FIXED       <a href="index.php?a=1&b=2" >ok</a>
```

The injected handler is a real attribute in the output, not an encoded string. After
the patch the same inputs produce `href="&quot; onmouseover=&quot;alert(1)"` — inert
text inside the attribute — and the benign URL still renders as a working link.

## Exploitability

This is a library primitive, so impact depends entirely on callers. It is exploitable
wherever a caller passes attacker-influenced data as `$url` or as an array attribute
value — most realistically a URL built from request input, or a title or label drawn
from user-supplied content.

Core's own call sites were not individually audited for this backport. The patch
fixes the primitive, which is where upstream fixed it; it does not prove any
particular core page was exploitable.

## The fix

Backported verbatim in behaviour from Joomla 5.4.9. Escape the URL, escape the name
in `iframe()`, and route array attributes through a new `escapeAttributesArray()`
helper that escapes values and drops syntactically invalid attribute names:

```php
$attribs = ArrayHelper::toString(self::escapeAttributesArray($attribs));
$url     = htmlspecialchars((string) $url, ENT_QUOTES, 'UTF-8', false);
```

The fourth argument to `htmlspecialchars()` is `double_encode = false`, matching
upstream. This matters: callers that already pass an escaped URL containing `&amp;`
will not see it mangled into `&amp;amp;`.

`$text` is deliberately **not** escaped. Callers legitimately pass markup as link
text — icons, `<span>` wrappers — and escaping it would break them. This matches
upstream. Treat `$text` as a trusted-HTML parameter and escape it at the call site
when it comes from user input.

### Deviations from upstream

Presentation only, to keep the 3.10 branch's PHP floor and code style:

- `escapeAttributesArray()` is declared without the `array` parameter type's
  companion `: array` return type that upstream uses, and without scalar type hints,
  for PHP 5.3 compatibility.
- Joomla 3 brace-on-next-line style is used rather than Joomla 4+ style.

## Behaviour change

URLs passed to `link()` and `iframe()` are now escaped. Any caller that was passing
pre-built markup through the `$url` argument — never a supported use — will see it
escaped and rendered inert. Array attribute names that are not valid HTML attribute
names are now dropped rather than emitted.
